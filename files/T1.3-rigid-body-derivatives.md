## Background

This is the heart of the simulator: one function that answers "given where the
aircraft is and what forces act on it, how fast is everything changing?"

At this stage the aircraft has no wings and no engine. It is a heavy object with
an inertia tensor, floating in space, with gravity acting on it. That is
deliberate — you want to verify Newton and Euler before you add aerodynamics,
because once aerodynamics are in, a bug here becomes almost impossible to
isolate.

Two terms in these equations are the ones people get wrong. The Coriolis term
`omega × v` appears in the translational equation because the body frame is
rotating. The gyroscopic term `omega × (I omega)` appears in the rotational
equation for the same reason. Omit either and the simulator will run happily and
be wrong. The Phase 1 gate tests exist specifically to catch this.

## What to implement

```python
def gravity_body(quat: np.ndarray, mass: float) -> np.ndarray:
    """
    Gravity force in the body frame.

        F_grav_b = m * R_nb^T @ [0, 0, g]

    Note the transpose: R_nb maps body->NED, so its transpose maps NED->body.
    Getting this backwards makes the aircraft fall upward when banked.

    Args:  quat: (4,);  mass: kg
    Returns: (3,) force in body frame, N
    """

def rigid_body_derivatives(x: np.ndarray,
                           F_b: np.ndarray,
                           M_b: np.ndarray,
                           cfg: AircraftConfig) -> np.ndarray:
    """
    Nonlinear 6-DOF rigid-body state derivative.

    Implements:
        pdot_n   = R_nb @ v_b
        vdot_b   = F_b/m - omega_b x v_b
        quatdot  = 0.5 * Omega(omega_b) @ quat
        omegadot = I^-1 (M_b - omega_b x (I omega_b))

    Args:
        x:    (13,) state
        F_b:  (3,) TOTAL force in body frame, N, INCLUDING gravity
        M_b:  (3,) TOTAL moment about the CG in body frame, N.m
        cfg:  AircraftConfig (uses mass.m, mass.inertia_tensor)

    Returns:
        (13,) state derivative

    This function is pure: no I/O, no globals, no mutation of inputs.

    Reference: Stevens & Lewis 3rd ed., eqns 1.7-18 and 1.7-19
    """
```

Written out, so there is no ambiguity:

```
udot = F_x/m - q*w + r*v
vdot = F_y/m - r*u + p*w
wdot = F_z/m - p*v + q*u
```

and

```
omegadot = I_inv @ (M_b - cross(omega_b, I @ omega_b))
```

Use `cfg.mass.inertia_inverse`, precomputed in T0.3 — do not call `np.linalg.inv`
inside this function. It is called five million times per Monte Carlo campaign.

## Acceptance criteria

- [ ] Zero force, zero moment, zero initial rates, level attitude → derivative
      is all zeros except `pdot_n`
- [ ] Pure `+x_b` force with zero rates produces `udot = F/m` exactly
- [ ] Coriolis check: with `v_b = [V, 0, 0]` and `omega_b = [0, 0, r]`, the
      result must be `vdot = -r*V` in the `y` component. Assert the sign
- [ ] Gyroscopic check: with `omega_b = [1, 1, 0]` and a diagonal inertia with
      `I_xx ≠ I_yy`, `omegadot[2]` must be non-zero. If it is zero you have
      dropped the `omega × (I omega)` term
- [ ] Gravity: level attitude gives `F_grav_b = [0, 0, +m*g]`; 90° pitch-up
      gives `[-m*g, 0, 0]`. Assert both
- [ ] The function does not modify `x`, `F_b` or `M_b` in place
- [ ] Returns shape `(13,)`, dtype float64

## Notes

Common failure: writing `vdot = F/m + omega × v` instead of `- omega × v`. The
sign follows from transport theorem — the derivative of a vector in a rotating
frame. The Coriolis acceptance test above catches it in one line.

Do not add aerodynamics here. `dynamics.py` must never import `aero.py`. The
force and moment arguments come in from outside; that separation is what lets
you swap the aerodynamic model in Phase 8 without touching this file.
