## Background

This is the first gate. Everything above it in the project — every controller,
every optimisation, every Monte Carlo result — rests on the equations you just
wrote. If gravity has the wrong sign or the gyroscopic term is missing, none of
it means anything, and you will not find out for two months.

These five tests are not unit tests. They are physics checks: each one asserts a
conservation law or an analytic solution that must hold regardless of how you
implemented things. That is what makes them trustworthy.

Test 4 is the important one. It is the test that catches the single most common
bug in 6-DOF simulators.

## What to implement

All tests marked `@pytest.mark.gate`. All tolerances written into the test.

**Test 1 — Free fall.** No forces except gravity, level attitude, at rest.
After `t` seconds the aircraft must have fallen exactly `0.5 * g * t²`.

```python
@pytest.mark.gate
def test_free_fall_matches_analytic(cfg):
    x0 = make_state(pos_n=[0,0,-1000], vel_b=[0,0,0],
                    quat=[1,0,0,0], omega_b=[0,0,0])
    res = simulate_gravity_only(x0, duration=10.0, cfg=cfg)
    fallen = res.x[-1, 2] - res.x[0, 2]         # +ve because down is +ve
    assert fallen == pytest.approx(0.5 * G0 * 10.0**2, abs=1e-9)
```

Catches: gravity sign errors, integration bugs, the `p_D` sign confusion.

**Test 2 — Ballistic trajectory.** Launch at 45° with speed `V0`, gravity only.
Range must equal `V0² · sin(2·45°) / g`, and the apex must equal
`V0² sin²(45°) / (2g)`, both to 1e-6 relative.

Catches: rotation matrix transposition, frame confusion between body and NED.

**Test 3 — Quaternion norm.** Constant non-zero `omega` for 100 s. Norm must
stay within 1e-10 of 1 at every logged step, not just the last one.

Catches: missing renormalisation, wrong `Omega` matrix.

**Test 4 — Angular momentum conservation.** Torque-free body with an asymmetric
inertia tensor and an initial rate about an intermediate axis.

```python
@pytest.mark.gate
def test_angular_momentum_conserved_torque_free(cfg):
    """
    A torque-free asymmetric body must TUMBLE (the intermediate axis theorem)
    while conserving angular momentum in the INERTIAL frame.

    This is the test that catches a missing omega x (I omega) term, which is
    the single most common bug in 6-DOF simulators. A simulator missing that
    term will keep omega constant and pass a naive test.
    """
    x0 = make_state(..., omega_b=[0.1, 2.0, 0.05])   # spin about intermediate axis
    res = simulate_torque_free(x0, duration=30.0, cfg=cfg)

    H_inertial = np.array([
        quat_to_dcm(row[IDX_QUAT]) @ (cfg.mass.inertia_tensor @ row[IDX_OMEGA])
        for row in res.x
    ])
    drift = np.abs(H_inertial - H_inertial[0]).max()
    assert drift < 1e-8

    # And it must actually tumble, otherwise the term is missing
    assert res.x[:, IDX_OMEGA][:, 0].ptp() > 0.5
```

**Test 5 — Energy conservation.** Torque-free, force-free. Total kinetic energy
`0.5·m·|v|² + 0.5·omegaᵀ·I·omega` constant to 1e-8 relative over 60 s.

Catches: sign errors that inject energy; unstable integration.

- [ ] Deliberately break each of the five things (flip gravity sign, delete the

- [ ] Tagged `git tag phase-1-complete`

## Notes

The "deliberately break it" step is not optional busywork — it is the only way
to know the gate works. Do it once, properly, and write down in the commit
message which test caught which injected fault.

If test 4 fails, do not proceed and do not start debugging your controller
later. Fix `omega × (I omega)` now.
