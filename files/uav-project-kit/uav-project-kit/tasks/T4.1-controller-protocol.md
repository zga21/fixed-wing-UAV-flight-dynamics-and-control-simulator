## Background

You are going to build two controllers and compare them. For that comparison to
mean anything, they must be interchangeable — same inputs, same outputs, same
harness, same scenarios. This task defines the contract that makes the swap
possible, before either controller exists.

Doing this now rather than retrofitting it in Phase 6 is the difference between a
clean comparison and a week of refactoring under time pressure.

## What to implement

```python
@dataclass(frozen=True)
class Reference:
    """What the guidance layer is asking for."""
    altitude: float | None = None      # m
    airspeed: float | None = None      # m/s
    heading: float | None = None       # rad
    roll: float | None = None          # rad, for direct attitude commands
    pitch: float | None = None
    waypoint_n: np.ndarray | None = None

@dataclass(frozen=True)
class Controls:
    delta_a: float; delta_e: float; delta_r: float; delta_t: float
    def to_array(self) -> np.ndarray: ...

class Controller(Protocol):
    """
    Both the Phase 4 PID and the Phase 6 NDI implement this.

    Implementations MUST:
      - take the ESTIMATED state, never the true state (Phase 5 makes the
        distinction real; wiring it now means no changes later)
      - be resettable
      - expose their tunable parameters as a flat vector for Phase 7
    """
    def update(self, x_hat: np.ndarray, ref: Reference,
               t: float, dt: float) -> Controls: ...
    def reset(self) -> None: ...
    @property
    def gains(self) -> np.ndarray: ...
    @gains.setter
    def gains(self, k: np.ndarray) -> None: ...
    @property
    def gain_names(self) -> list[str]: ...
    @property
    def gain_bounds(self) -> list[tuple[float, float]]: ...
```

The `gains` vector interface is what Phase 7's optimiser drives. Defining it now
means CMA-ES works on both controllers with no special-casing.

## Acceptance criteria

- [ ] A trivial `ZeroController` implements the protocol and runs in `simulate`
- [ ] `gains` round-trips: set a vector, read it back, get the same values
- [ ] `gain_names` and `gain_bounds` have the same length as `gains`
- [ ] `reset()` clears all integrator state — verify by running, resetting, and
      confirming an identical second run
- [ ] `runtime_checkable` isinstance check passes

## Notes

Take the argument `x_hat`, not `x`. In Phase 4 you will pass the true state
because there is no estimator yet, but naming it `x_hat` from the start means
Phase 5 changes one line in the harness instead of every controller.
