## Background

The controller needs to know the aircraft's state, but the sensors give noisy,
biased, intermittent measurements of parts of it. The Extended Kalman Filter
fuses them into a best estimate.

The intuition: the filter has a physics model, so it can *predict* where the
aircraft should be a moment from now. It also has a measurement. Neither is
perfect, so it blends them, weighted by how much it trusts each — and it tracks
its own uncertainty, so the weighting adapts. When GPS drops out it leans on the
model; when the model drifts it leans on GPS.

For the project, the EKF matters because it introduces **estimation error and
lag** into the control loop. Both controllers must use the same estimator, or the
Phase 6 comparison is measuring the estimator rather than the controller.

## What to implement

```python
class NavigationEKF:
    """
    Predict:
        x_hat_minus = f(x_hat, u)
        P_minus     = F P F^T + Q
    Update (per sensor, at that sensor's rate):
        K = P_minus H^T (H P_minus H^T + R)^-1
        x_hat = x_hat_minus + K (y - h(x_hat_minus))
        P     = (I - K H) P_minus

    States: position (3), velocity (3), quaternion (4), gyro bias (3),
            accel bias (3).  15 error states in the error-state formulation.
    """
    def __init__(self, cfg, Q, R_dict, x0, P0): ...
    def predict(self, imu: IMUMeasurement, dt: float) -> None: ...
    def update_gps(self, gps) -> None: ...
    def update_baro(self, baro) -> None: ...
    def update_airspeed(self, pitot) -> None: ...
    def update_magnetometer(self, mag) -> None: ...
    @property
    def state(self) -> np.ndarray:
        """(13,) estimate in the same layout as the true state."""
    @property
    def covariance_diagonal(self) -> np.ndarray:
        """For monitoring and for the Phase 9 confidence analysis."""
```

Prefer the **error-state (indirect) formulation** for the quaternion: propagate
the nominal quaternion with the gyro, and estimate a small-angle error which is
injected and reset each update. It avoids the unit-norm constraint problem
entirely and is what real flight software does.

Use Joseph-form covariance updates for numerical stability, and enforce symmetry
with `P = 0.5*(P + P.T)` after each update.

## Acceptance criteria

- [ ] **Converges.** Attitude error settles below 2° RMS in steady flight
- [ ] **Recovers.** From a 30° initial attitude error, converges within 10 s
- [ ] **Estimates bias.** Gyro bias estimate converges to the true injected bias
      within 20%
- [ ] **Covariance behaves.** `P` stays positive-definite and symmetric for
      600 s. Assert `np.linalg.eigvalsh(P).min() > 0` throughout
- [ ] **Consistency (NEES).** The normalised estimation error squared is inside
      its chi-squared bounds for ~95% of samples. This is the proper test of an
      EKF: a filter that is confidently wrong will pass an RMS test and fail this
- [ ] **GPS dropout.** With GPS removed for 10 s, position error grows smoothly
      rather than diverging, and recovers on reacquisition
- [ ] Ideal sensors give near-zero estimation error
- [ ] Deterministic given a seed

## Notes

Do not over-invest here. The EKF is a means to an end — the research questions
are about control, not estimation. If tuning it is consuming days, use a simpler
complementary filter for attitude plus direct GPS for position, document that
choice in the report's limitations section, and move on. A working simple
estimator that both controllers share is worth more than a sophisticated one that
delays Phase 6 by three weeks.
