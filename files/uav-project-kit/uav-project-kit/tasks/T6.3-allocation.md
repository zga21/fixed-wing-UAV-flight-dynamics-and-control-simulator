## Background

NDI computes the moments it wants. Allocation decides which surfaces produce
them.

With exactly three surfaces and three axes the answer is a plain matrix inverse.
It gets interesting when surfaces saturate: if the aileron hits its stop, naively
inverting produces a command that cannot be delivered, and the resulting moment
is wrong in *all three axes* rather than just the saturated one.

Even with three surfaces, aileron and rudder both produce yaw and roll, so a
saturated aileron corrupts the yaw axis too. Handling that is what separates a
controller that degrades gracefully from one that falls apart at the envelope
edge.

## What to implement

```python
def pseudo_inverse_allocation(G, nu, W=None) -> np.ndarray:
    """
    Weighted least-squares allocation:
        delta = W^-1 G^T (G W^-1 G^T)^-1 nu
    W lets you prefer some surfaces over others (e.g. prefer aileron over
    rudder for roll, because rudder use costs drag).
    """

def redistributed_allocation(G, nu, limits, max_iter=5) -> AllocationResult:
    """
    Handle saturation properly:
      1. allocate
      2. if any surface exceeds its limit, clamp it
      3. subtract the moment the clamped surface actually delivers
      4. re-allocate the REMAINDER among the free surfaces
      5. repeat until nothing new saturates or max_iter

    Returns the commands plus the unachievable moment residual, so the
    controller knows what it failed to deliver and can stop winding up its
    integrator against it.
    """

@dataclass(frozen=True)
class AllocationResult:
    delta: np.ndarray
    residual: np.ndarray       # moment that could NOT be produced
    saturated: np.ndarray      # bool per surface
    iterations: int
```

Feed `residual` back to the integrator as an anti-windup signal — it is the
multivariable equivalent of the back-calculation in T4.2.

## Acceptance criteria

- [ ] Unsaturated case matches a plain `np.linalg.solve` to 1e-10
- [ ] **Saturation handled.** With a moment demand that saturates the aileron,
      the achieved roll moment equals the maximum achievable, and the pitch and
      yaw axes are still delivered correctly. Compare against naive inversion
      and assert the naive version is worse in the unsaturated axes
- [ ] `residual` is zero when nothing saturates and non-zero when something does
- [ ] Converges within `max_iter` for all reachable demands
- [ ] Handles a fully saturated case without looping forever
- [ ] Weighting `W` shifts effort between surfaces as expected

## Notes

If you extend the aircraft to more surfaces later — split ailerons, elevons, a
V-tail — this module absorbs the change and nothing else does. That is worth
noting in the report as an architectural point: control allocation as a separate
layer is standard practice in modern flight control for exactly this reason.
