## Background

One test flight proves nothing — you might have been lucky with the wind. So you
build ten thousand slightly different aircraft: one heavier, one with weaker
wings, one in nastier gusts, one with a servo at the slow end of tolerance.

This task defines *how different* they are allowed to be. The distributions are
judgement calls and they must be defensible, because your headline number means
nothing without them: "97% success" is only meaningful alongside "across this
specific uncertainty set."

Separating **epistemic** uncertainty (things you do not know, like the true
`C_m_alpha` — reducible with better data) from **aleatoric** uncertainty (things
that are genuinely random, like gusts — irreducible) is what makes the analysis
rigorous rather than decorative.

## What to implement

From the build guide:

| Parameter | Distribution | Type |
|-----------|--------------|------|
| `m` | `N(m0, (0.05 m0)^2)` | aleatoric |
| `x_cg` | `U(-0.03 c, +0.03 c)` | aleatoric |
| `I_xx, I_yy, I_zz` | `N(I0, (0.10 I0)^2)` | epistemic |
| `C_L_alpha, C_m_alpha` | `N(C0, (0.15 C0)^2)` | epistemic |
| `C_m_q, C_l_p, C_n_r` | `N(C0, (0.20 C0)^2)` | epistemic |
| Wind speed | `U(0, 12)` m/s | aleatoric |
| Wind direction | `U(0, 2 pi)` | aleatoric |
| Turbulence intensity | light/moderate/severe, `p = [0.5, 0.35, 0.15]` | aleatoric |
| Actuator `tau` | `U(0.03, 0.08)` s | epistemic |
| Sensor noise seed | derived from case seed | aleatoric |

def sample_parameters(rng: np.random.Generator,

    Draw one parameter set. ALL randomness from the passed rng.

    Rejects and redraws physically impossible combinations: negative mass,

Write `docs/uncertainty_justification.md` **before** running anything, citing a
reason for each spread: manufacturing tolerance, typical wind-tunnel measurement
error, published sensor datasheets, local meteorological statistics. The
justification is what a reviewer will probe, and writing it first stops you from
quietly widening a distribution later to make a result look better.

## Acceptance criteria

- [ ] Sampled marginals match the specification: mean and standard deviation
      within 2% over 100,000 draws
- [ ] Physically impossible combinations are rejected — verify by forcing one
- [ ] Reproducible: same rng seed gives the same parameter set, bit for bit
- [ ] Every parameter tagged epistemic or aleatoric
- [ ] `docs/uncertainty_justification.md` gives a source or rationale per line
- [ ] Correlations are handled deliberately: `I_xx`, `I_yy` and `I_zz` should
      probably be correlated (a heavier aircraft is heavier everywhere), and
      sampling them independently is a modelling choice you should either fix or
      justify in writing

## Notes

Getting the spreads wrong in either direction undermines the result. Too narrow
and 100% success is meaningless. Too wide and both controllers fail, which is
also uninformative. If your first pilot run shows the baseline succeeding 99.8%
of the time, the uncertainty set is too gentle to discriminate — widen it, and
say in the report that you did and why.
