## Background

This task builds the aerodynamic model — and, more importantly, the *interface*
to it.

The physical idea is a trick engineers use everywhere. The force on a wing
depends on speed, air density, wing size and shape, and the angle it meets the
air. Rather than tangle all of that together, you split it: a part that depends
on speed and size (easy, always the same formula) and a dimensionless
**coefficient** that captures the shape and angle. Estimate the coefficients
once, and the model works at every speed and altitude.

The interface matters as much as the maths. Right now you build a linear model:
lift coefficient is a constant plus a slope times angle of attack. Later, in
Phase 8, a Gaussian Process will predict corrections to it. If both implement the
same protocol, that swap requires **zero changes** to `dynamics.py` — which is
the whole architectural bet of the project.

## What to implement

```python
@dataclass(frozen=True)
class AeroCoeffs:
    C_L: float; C_D: float; C_Y: float      # forces (wind axes for L, D)
    C_l: float; C_m: float; C_n: float      # moments (body axes)

class AeroModel(Protocol):
    """
    THE SWAP POINT of the project.

    Implementations:
      Phase 2:  LinearAeroModel     - derivative build-up
      Phase 8:  GPResidualAero      - physics + learned correction
      optional: TableAeroModel      - nonlinear lookup, the 'truth' model

    Anything implementing this protocol drops into the simulator without
    changes to dynamics.py, integrate.py or any controller.
    """
    def coefficients(self, air: AirData, omega_b: np.ndarray,
                     controls: np.ndarray, geom: Geometry) -> AeroCoeffs: ...

class LinearAeroModel:
    def __init__(self, derivs: AeroDerivatives): ...
    def coefficients(self, air, omega_b, controls, geom) -> AeroCoeffs: ...
```

The build-up, with the non-dimensional rates written explicitly:

```
p_hat = p * b / (2V)        q_hat = q * c_bar / (2V)        r_hat = r * b / (2V)

C_L = C_L_0 + C_L_alpha*alpha + C_L_q*q_hat + C_L_delta_e*delta_e
C_D = C_D_0 + C_L**2 / (pi * e * AR)                    # AR = b^2 / S
C_Y = C_Y_beta*beta + C_Y_p*p_hat + C_Y_r*r_hat
      + C_Y_delta_a*delta_a + C_Y_delta_r*delta_r

C_l = C_l_beta*beta + C_l_p*p_hat + C_l_r*r_hat
      + C_l_delta_a*delta_a + C_l_delta_r*delta_r
C_m = C_m_0 + C_m_alpha*alpha + C_m_q*q_hat + C_m_delta_e*delta_e
C_n = C_n_beta*beta + C_n_p*p_hat + C_n_r*r_hat
      + C_n_delta_a*delta_a + C_n_delta_r*delta_r
```

**The `2V` denominator matters.** Non-dimensionalising rates by `b/(2V)` is what
makes damping derivatives speed-independent. Forget it and your aircraft will be
correctly damped at one airspeed and wrong everywhere else — which will look
exactly like a controller tuning problem and waste days.

Guard against `V → 0`: clamp `V` to `V_MIN_AERO` when forming `p_hat`, `q_hat`,
`r_hat`.

**Optional but recommended: a stall model.** Blend the linear `C_L` into a
flat-plate model beyond `alpha_stall` with a sigmoid:

```python
sigma = (1 + exp(-M*(alpha - a0)) + exp(M*(alpha + a0))) / \
        ((1 + exp(-M*(alpha - a0))) * (1 + exp(M*(alpha + a0))))
C_L = (1 - sigma) * C_L_linear + sigma * C_L_flat_plate
```

This keeps the model honest near the envelope edge, and it gives Phase 8's GP
something real to learn a residual against.

## Acceptance criteria

- [ ] `C_L` increases monotonically with `alpha` over `[-5°, +10°]`
- [ ] `C_m` **decreases** with `alpha` (i.e. `C_m_alpha < 0`) — static stability
- [ ] `C_D` is minimised near `alpha` for minimum `C_L`, and is always positive
- [ ] **Symmetry.** With `beta = 0`, `delta_a = 0`, `delta_r = 0`, `p = r = 0`:
      `C_Y`, `C_l` and `C_n` are **exactly zero**, not approximately. Use
      `assert C_Y == 0.0`. A symmetric aircraft in symmetric flight cannot
      produce a lateral force
- [ ] Positive `delta_e` produces negative `C_m` (nose-down), per T0.2
- [ ] Positive `delta_a` produces positive `C_l` (right roll)
- [ ] Doubling `V` with the same dimensional rates halves `p_hat`, `q_hat`, `r_hat`
- [ ] `V = 0` does not produce NaN or inf
- [ ] `LinearAeroModel` satisfies `isinstance(model, AeroModel)` under
      `runtime_checkable`

## Notes

Keep `coefficients` a **pure function of its arguments**. No internal state, no
caching keyed on previous calls. Phase 7 evaluates this millions of times across
parallel workers and Phase 8 replaces it with a GP; both break if it is stateful.

If you later add a `TableAeroModel` as a higher-fidelity "truth" for Phase 8,
build it behind this same protocol. The residual you learn is then exactly the
difference between two implementations of one interface, which is a clean and
defensible experimental design.
