## Background

The derivative function says how fast things are changing right now. The
integrator uses that to step the state forward in time. Classical fourth-order
Runge–Kutta evaluates the derivative four times per step and combines them,
which is far more accurate than a naive Euler step for the same cost.

Fixed-step is chosen deliberately over an adaptive solver: Monte Carlo runs then
have deterministic, comparable cost and bit-identical reproducibility, which
Phase 9 depends on completely.

One subtlety: the quaternion drifts off unit norm as you integrate. You
renormalise after each *completed* step, not inside the RK4 stages — normalising
mid-stage corrupts the derivative estimates.

## What to implement

```python
def rk4_step(deriv_fn: Callable, t: float, x: np.ndarray,
             dt: float, *args) -> np.ndarray:
    """
    One classical RK4 step, with quaternion renormalisation on exit.

        k1 = f(t, x)
        k2 = f(t + dt/2, x + dt/2 * k1)
        k3 = f(t + dt/2, x + dt/2 * k2)
        k4 = f(t + dt,   x + dt   * k3)
        x_next = x + dt/6 * (k1 + 2k2 + 2k3 + k4)

    Renormalises x_next[IDX_QUAT] AFTER the full step, never between stages.
    """

@dataclass
class SimResult:
    """Time histories. Arrays are (n_steps, ...) with time as axis 0."""
    t: np.ndarray             # (N,)
    x: np.ndarray             # (N, 13)
    u: np.ndarray             # (N, 4)  commanded controls
    u_actual: np.ndarray      # (N, 4)  post-actuator (Phase 5)
    diagnostics: dict         # alpha, beta, V, forces, etc.
    terminated_early: bool
    termination_reason: str | None

    def to_dict(self) -> dict: ...          # for JSON export, Phase 10
    def metrics(self) -> dict: ...          # populated in T4.6

def simulate(x0: np.ndarray,
             controller,
             duration: float,
             cfg: AircraftConfig,
             plant,
             log_every: int = 1,
             rng: np.random.Generator | None = None) -> SimResult:
    """
    Main simulation loop.

    Terminates early and records the reason if:
      - any state is NaN or inf
      - altitude goes below zero (ground impact)
      - |V| exceeds 3x the envelope maximum (divergence)

    Early termination is NOT an exception. Phase 9 needs a result object back
    for every case, including the ones that failed, so it can count them.
    """
```

Log at a decimated rate (`log_every`) rather than every 500 Hz step. A 60-second
Monte Carlo case logged at full rate is 30,000 rows × 13 states × 10,000 cases,
which is a lot of disk for nothing. Log at 50 Hz and keep full rate only for the
handful of trajectories you export in Phase 10.

## Acceptance criteria

- [ ] **Order check.** Integrate a known ODE with an analytic solution (e.g.
      `xdot = -x`, `x(0) = 1`). Halving `dt` must reduce the error by a factor
      of ~16. If it reduces by 2, you have written Euler; by 4, you have
      written RK2
- [ ] **Step convergence.** Simulate 30 s of ballistic flight at `dt = 0.002`
      and at `dt = 0.001`. Trajectories must agree to within 0.1%
- [ ] **Quaternion norm.** After 100 s with constant `omega = [0.1, 0.2, 0.3]`,
      norm is within 1e-10 of 1
- [ ] **Determinism.** Two identical calls return bit-identical arrays. Use
      `np.testing.assert_array_equal`, not `allclose`
- [ ] **Early termination.** Force a NaN and confirm `simulate` returns a
      `SimResult` with `terminated_early=True` and a reason string, rather than
      raising
- [ ] Simulating 60 s at 500 Hz takes under ~2 s. If it is much slower, profile
      before continuing — Phase 9 will run this 20,000 times

## Notes

Do not reach for `scipy.integrate.solve_ivp` here. Adaptive stepping makes the
cost of a Monte Carlo case depend on the case, which breaks the fixed-budget
parallel scheduling in Phase 9, and adaptive error control interacts badly with
the discontinuities that actuator rate limits introduce in Phase 5.

Performance note: preallocate the log arrays with `np.empty((n_steps, 13))`
rather than appending to a list. It is a 3–5x difference at this loop rate.
