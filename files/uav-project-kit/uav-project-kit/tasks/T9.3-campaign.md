## Background

Twenty thousand cases (10,000 seeds × 2 controllers) at roughly one second each
is about six hours on eight cores. Long enough that a crash at hour five is
genuinely painful, so the campaign must be resumable.

The critical design decision is **pairing**. Both controllers must run on the
*same* seeds, so that case 4271 gives both the identical aircraft, wind, sensor
noise and initial conditions. That pairing is what makes McNemar's test valid in
T9.4, and it roughly doubles your effective statistical power for free.

## Acceptance criteria

- [ ] 20,000 cases complete without a crash
- [ ] **Pairing verified.** For every seed, both controllers received identical
      sampled parameters. Assert this on the results frame — it is the
      assumption the whole statistical analysis rests on
- [ ] Kill the process mid-run and restart: it resumes, and the final result is
      identical to an uninterrupted run
- [ ] Parallel and serial give identical results
- [ ] `manifest.json` contains git commit, config hash, spec hash, timestamps,
      worker count and the dirty flag
- [ ] Dirty working tree is refused without an explicit override
- [ ] Convergence plot generated: success rate versus N, flat over the last
      2000 cases
- [ ] Wall time and per-case timing recorded
- [ ] Part files concatenate cleanly into one frame

## Notes

Run a 200-case pilot campaign first, every time, before committing to the full
run. Check the failure rate is in a sensible range (not 0%, not 100%), check the
timing extrapolates to something you are willing to wait for, and check the
schema is what the analysis expects. Twenty minutes here saves a wasted overnight
run more often than you would think.

If the success rate is 100% for both controllers, the uncertainty set from T9.1
is too gentle to discriminate. Widen it and re-run — and say in the report that
you did, and why.
