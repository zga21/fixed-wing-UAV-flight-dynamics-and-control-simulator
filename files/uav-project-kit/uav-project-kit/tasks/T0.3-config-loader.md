## Background

Every component in the simulator needs aircraft parameters, and none of them
should read a file to get them. Configuration is loaded once, validated once,
frozen, and passed down. This keeps physics functions pure — which is what makes
them testable in Phase 1 and parallelisable in Phase 9.

Validation matters more than it looks. A typo that turns `I_yy: 1.135` into
`I_yy: 1135` will not crash anything; it will produce an aircraft that responds
sluggishly in pitch, and you will spend two days tuning a controller against a
typo. Pydantic catches the class of errors where a value is missing, negative,
or the wrong type.

**`src/uav_sim/config.py`** — schema, validation, and the derived quantities:

```python
from pydantic import BaseModel, Field, field_validator

class MassProperties(BaseModel, frozen=True):
    m: float = Field(gt=0)
    I_xx: float = Field(gt=0)
    I_yy: float = Field(gt=0)
    I_zz: float = Field(gt=0)
    I_xz: float = 0.0
    x_cg_frac: float = Field(ge=0, le=1)

    @property
    def inertia_tensor(self) -> np.ndarray:
        """(3,3) inertia tensor with the standard I_xz sign convention."""

    @property
    def inertia_inverse(self) -> np.ndarray:
        """Precomputed inverse. Computed once here, never inside the loop."""

class AeroDerivatives(BaseModel, frozen=True):
    ...
    @field_validator("C_m_alpha", "C_m_q", "C_l_p", "C_n_r")
    @classmethod
    def must_be_negative(cls, v, info):
        if v >= 0:
            raise ValueError(
                f"{info.field_name} must be negative for a stable, damped "
                f"aircraft. Got {v}. Check your sign convention (T0.2)."
            )
        return v

class AircraftConfig(BaseModel, frozen=True):
    name: str
    mass: MassProperties
    geometry: Geometry
    aero: AeroDerivatives
    ...

def load_aircraft(path: str | Path) -> AircraftConfig:
    """Load, validate, convert degrees to radians, freeze. Raises on any
    inconsistency rather than silently accepting it."""

def config_hash(cfg: AircraftConfig) -> str:
    """Short stable hash of the config, recorded in every results file."""
```

## Acceptance criteria

- [ ] `load_aircraft("config/aircraft_v1.yaml")` returns a frozen object
- [ ] Attempting to mutate any field raises
- [ ] A config with `C_m_alpha = +0.38` raises a `ValidationError` whose message
      names the field and points at the sign convention
- [ ] A config missing a required key raises, naming the key
- [ ] All angle fields are radians on the loaded object; only `*_deg` fields in
      YAML are degrees
- [ ] `inertia_tensor` is symmetric and positive-definite (assert this in a test)
- [ ] `config_hash` is stable across runs and changes when any value changes

## Notes

The negative-derivative validator is not pedantry. `C_m_alpha > 0` means a
statically unstable aircraft that diverges in pitch, and the failure mode is
that you blame your controller for a week. Catching it at load time costs five
lines.
