## Background

Up to now you have flown the aircraft by hand from test code. From here on
everything — the Phase 4 baseline record, the Phase 6 comparison, the Phase 7
objective function, the Phase 9 campaign — needs the same thing: run a defined
mission and reduce it to a handful of numbers.

Defining those numbers **now**, before you have any results, matters. If you
choose metrics after seeing the data, you will unconsciously choose the ones that
make your controller look good. Quantitative success criteria should be defined
before controller optimisation begins.

## What to implement

**Scenario definition** — declarative, version-controlled:

```yaml
# config/scenarios/mission_a.yaml
name: mission_a_climb_turn_cruise
duration: 180.0
initial: {V: 25.0, altitude: 100.0, heading: 0.0}
segments:
  - {t: 0,   altitude: 100, airspeed: 25, heading: 0}
  - {t: 20,  altitude: 200, airspeed: 25, heading: 0}      # climb
  - {t: 60,  altitude: 200, airspeed: 30, heading: 90}     # accel + turn
  - {t: 110, altitude: 150, airspeed: 25, heading: 180}    # descend + turn
  - {t: 160, altitude: 150, airspeed: 22, heading: 180}    # decelerate
```

**Metrics** — every one of these is referenced by later phases:

```python
@dataclass(frozen=True)
class Metrics:
    rmse_h: float; rmse_V: float; rmse_phi: float; rmse_theta: float
    max_h_error: float; max_V_error: float
    overshoot_h: float; settling_time_h: float
    control_effort: float          # integral of u^T R u
    control_rate_effort: float     # integral of |udot|^2
    saturation_fraction: float     # fraction of time any surface is saturated
    envelope_violations: int
    max_load_factor: float
    disturbance_recovery_time: float
    integration_failures: int
    terminated_early: bool
    success: bool                  # against the criteria below

SUCCESS_CRITERIA = {
    "rmse_h": 5.0,          # m
    "rmse_V": 1.5,          # m/s
    "max_phi_deg": 60.0,
    "saturation_fraction": 0.10,
    "envelope_violations": 0,
}

def compute_metrics(result: SimResult, scenario: Scenario) -> Metrics: ...
def run_scenario(scenario, controller, plant, cfg,
                 seed: int | None = None) -> tuple[SimResult, Metrics]: ...
```

Freeze `SUCCESS_CRITERIA` now and record the date you froze it. Phase 9's
headline number is defined entirely by this dictionary.

## Acceptance criteria

- [ ] At least three scenarios defined: `mission_a` (general), `step_responses`
      (isolated commands), `disturbance_rejection` (Phase 5 will add wind)
- [ ] Metrics computed on a synthetic perfect-tracking result give zero errors —
      a sanity check on the metric code itself
- [ ] RMSE computed only over segments where a command is active, not during
      transitions between them
- [ ] `run_scenario` is deterministic given a seed
- [ ] Metrics serialise to a flat dict for Parquet in Phase 9
- [ ] `SUCCESS_CRITERIA` frozen, dated, and committed in its own commit so the
      git history proves it predates the results

## Notes

Pay attention to what "settling time" means when the command is a ramp between
segments rather than a step. Define it explicitly in the docstring — reviewers
notice inconsistent metric definitions, and you will be comparing two controllers
on these numbers.
