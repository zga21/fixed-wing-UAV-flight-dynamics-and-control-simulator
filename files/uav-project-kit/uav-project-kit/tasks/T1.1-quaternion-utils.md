## Background

The aircraft's orientation has to be stored somehow. Euler angles (roll, pitch,
yaw) are the intuitive choice and they are what you will plot — but they have a
singularity at `theta = ±90°` where roll and yaw become indistinguishable and
the equations blow up. An agile aircraft will reach that attitude, so Euler
angles cannot be the internal representation.

A quaternion is four numbers that encode a rotation with no singularity
anywhere. The cost is that it is not human-readable, so you convert to Euler
angles at the output boundary and only there.

This task builds the small library of rotation operations everything else uses.
It is pure maths with no aircraft in it, which makes it easy to test exhaustively
— and worth testing exhaustively, because a transposed rotation matrix produces
an aircraft that behaves *almost* correctly and is miserable to debug.

The rotation matrix, written out so there is no ambiguity about the convention:

```
R_nb = [[q0²+q1²-q2²-q3²,  2(q1q2 - q0q3),   2(q1q3 + q0q2)],
        [2(q1q2 + q0q3),   q0²-q1²+q2²-q3²,  2(q2q3 - q0q1)],
        [2(q1q3 - q0q2),   2(q2q3 + q0q1),   q0²-q1²-q2²+q3²]]
```

The quaternion rate matrix:

```
Omega(omega) = [[ 0, -p, -q, -r],
                [ p,  0,  r, -q],
                [ q, -r,  0,  p],
                [ r,  q, -p,  0]]
```

Use `np.arctan2` in `quat_to_euler`, never `np.arctan`, and clip the argument of
`arcsin` to `[-1, 1]` to survive floating-point drift.

## Acceptance criteria

- [ ] `quat_to_dcm([1,0,0,0])` returns the identity matrix exactly
- [ ] `R.T @ R == I` to within 1e-12 for 1000 random unit quaternions
- [ ] `det(R) == +1` to within 1e-12 (a value of −1 means you have a reflection,
      i.e. a sign error)
- [ ] Round trip: `quat_to_euler(euler_to_quat(phi, theta, psi))` recovers the
      inputs to 1e-12 for 1000 random angles with `|theta| < 89°`
- [ ] Known case: a 90° yaw rotation maps body `x` to NED `y`. Assert this
      explicitly — it is the test that catches a transposed matrix
- [ ] Integrating `quat_derivative` with constant `omega = [0, 0, 0.1]` for
      2π/0.1 seconds returns to the starting quaternion (or its negation)
- [ ] `quat_normalise` raises on a near-zero quaternion rather than producing NaN

## Notes

`q` and `-q` represent the same rotation. Tests that compare quaternions
directly must account for this — compare rotation matrices, or compare
`min(|a - b|, |a + b|)`.

Do not use SciPy's `Rotation` class as the implementation. Write it yourself
here: this is one of the few places where implementing it from the convention
you wrote down is exactly the point. You may use SciPy in the *tests* as an
independent cross-check, which is a genuinely good use of it.
