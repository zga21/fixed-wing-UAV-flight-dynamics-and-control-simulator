## Background

Here is the idea, and it is a good one: do not replace the physics with a neural
network. Keep the physics and learn only the **difference** between what the
physics predicted and what actually happened. The equations do the heavy lifting;
the learned part fills the gaps.

A Gaussian Process is used rather than a neural network for one specific reason:
as well as predicting a value, it reports **how confident it is**. Ask it about a
flight condition far from anything it was trained on and it says, in effect, "I
have no idea here." A neural network will answer with the same confidence
everywhere, including where it is completely wrong — which is dangerous anywhere
near a control loop.

That uncertainty output is what makes T8.3 possible, and it is what makes this
phase a contribution rather than a bolt-on.

## What to implement

```python
class GPResidualAero(AeroModel):
    """
        C_hat = C_physics + C_GP

    Implements the SAME AeroModel protocol as LinearAeroModel, so it drops
    into the simulator with zero changes to dynamics.py. If you find yourself
    editing dynamics.py, the Phase 2 abstraction was wrong -- fix that instead.
    """
    def __init__(self, base: LinearAeroModel,
                 kernel=None, normalise_inputs=True): ...

    def fit(self, X: np.ndarray, residuals: np.ndarray) -> None:
        """
        One GP per coefficient. Inputs standardised before fitting -- the GP's
        length scales are meaningless if alpha (order 0.1) and V (order 25)
        share a scale.
        """

    def coefficients(self, air, omega_b, controls, geom) -> AeroCoeffs:
        """Physics prediction plus GP mean correction."""

    def uncertainty(self, air, omega_b, controls, geom) -> np.ndarray:
        """Predictive standard deviation per coefficient. Used by T8.3."""

    @property
    def length_scales(self) -> dict[str, float]:
        """Learned ARD length scales -- tells you WHICH inputs matter.
        A free interpretability result worth reporting."""
```

Kernel: squared exponential with automatic relevance determination, plus a white
noise term:

```
k(x, x') = sigma_f^2 * exp(-0.5 * sum_d (x_d - x'_d)^2 / l_d^2) + sigma_n^2 * delta
```

Fit hyperparameters by marginal likelihood with multiple restarts — the
likelihood surface is multimodal and a single restart often lands somewhere poor.

**Performance.** Exact GP inference is `O(n^3)` to fit and `O(n)` per prediction.
With 5000 training points, calling this at 500 Hz inside a simulation loop will
be far too slow for Phase 9. Two options: use a sparse GP with ~200 inducing
points, or precompute the GP onto a lookup grid and interpolate at run time. Pick
one and document it — do not discover this during the campaign.

## Acceptance criteria

- [ ] Held-out RMSE with the GP is lower than without it. If not, the GP is
      fitting noise — do not use it, and say so
- [ ] Length scales are physically sensible: alpha should matter most for `C_L`
      and `C_m`. If `V` dominates, suspect an input-scaling bug
- [ ] `sigma` grows as you move away from the training region. Query at
      `alpha = 25°` and confirm the standard deviation is several times the
      in-region value. **A model that is confidently wrong outside its training
      set must never go near a control loop**
- [ ] Satisfies `AeroModel`; the plant flies with it substituted
- [ ] **`dynamics.py` is unchanged.** Verify with `git diff` — this is the test
      of the Phase 2 architectural bet
- [ ] Prediction is fast enough for the campaign: under ~50 µs per call
- [ ] Fitting is reproducible from a seed

## Notes

If the GP is too slow even sparsified, the honest move is to use it as an
*analysis* tool rather than an in-loop model: keep the confidence map from T8.3
(which is the real contribution) and note in the report that in-loop deployment
was left to future work for computational reasons. That is a perfectly
respectable outcome and much better than a Phase 9 campaign that takes a week to
run.
