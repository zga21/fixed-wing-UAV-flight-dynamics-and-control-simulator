## Background

You now have all the pieces: rigid-body equations, aerodynamics, propulsion,
gravity, atmosphere. This task wires them into one object that the integrator can
step — a complete flying aircraft.

The key design constraint is that the plant owns the *composition* but not the
*physics*. It calls `aero_forces_moments`, `propeller_thrust` and
`rigid_body_derivatives`; it does not contain any equations of its own. That
keeps every physics function independently testable, and it means Phase 5 can
insert actuators and wind by wrapping the plant rather than editing it.

## What to implement

```python
class AircraftPlant:
    """
    Composes rigid-body dynamics with aerodynamics, propulsion and gravity.

    Owns no equations. Its only job is to call the physics functions in the
    right order and hand the totals to rigid_body_derivatives.
    """

    def __init__(self, cfg: AircraftConfig, aero_model: AeroModel,
                 wind_model=None, actuators=None):
        """wind_model and actuators are None in Phase 2, populated in Phase 5.
        Accepting them now means Phase 5 changes no call sites."""

    def derivatives(self, t: float, x: np.ndarray,
                    u: np.ndarray) -> np.ndarray:
        """
        Full state derivative for the integrator.

        1. wind_n     = wind_model(t, pos) if present else zeros
        2. air        = compute_air_data(vel_b, quat, altitude, wind_n)
        3. coeffs     = aero_model.coefficients(air, omega_b, u, geom)
        4. F_a, M_a   = aero_forces_moments(air, coeffs, geom)
        5. F_p, M_p   = propulsion_forces_moments(u[3], air, prop)
        6. F_g        = gravity_body(quat, mass)
        7. return rigid_body_derivatives(x, F_a+F_p+F_g, M_a+M_p, cfg)

        Pure with respect to (t, x, u) in Phase 2. In Phase 5 the wind model
        and actuators carry state, and reproducibility then depends on their
        rng being seeded per case.
        """

    def diagnostics(self, t, x, u) -> dict:
        """alpha, beta, V, q_bar, all force and moment contributions,
        separately. Logged for plots and for debugging; not used in the loop."""
```

## Acceptance criteria

- [ ] **Level flight persists.** Started near a hand-computed trim, the aircraft
      holds altitude within ~10 m over 30 s. It will not be perfect until T3.1
      solves trim properly, and that is fine
- [ ] **Pitch response is stable.** A small elevator doublet produces a damped
      oscillation that decays. If it grows, check `C_m_alpha` and `C_m_q` signs
- [ ] **Speed–altitude exchange.** Pull up with elevator: altitude increases and
      airspeed decreases. This is the phugoid, and seeing it is your first real
      sign that the whole model is behaving like an aircraft
- [ ] **Roll response.** Aileron step produces a roll rate that settles to a
      steady value (roll subsidence), not a divergence
- [ ] **Symmetric flight stays symmetric.** With zero lateral inputs from a
      wings-level start, `v`, `p`, `r`, `phi` and `psi` stay at exactly zero for
      60 s. This is a strong test — any coupling bug anywhere shows up here
- [ ] No NaN over a 120 s simulation
- [ ] 60 s of simulation completes in under ~3 s

## Notes

The symmetric-flight test is the single most valuable test in Phase 2. A
symmetric aircraft, symmetrically trimmed, with no lateral input, must stay
perfectly symmetric forever. Any nonzero `phi` after 60 seconds means something
somewhere is coupling axes that should not couple — a swapped index, a wrong
cross product, a sign error in `I_xz`. It catches an enormous class of bugs in
one assertion.
