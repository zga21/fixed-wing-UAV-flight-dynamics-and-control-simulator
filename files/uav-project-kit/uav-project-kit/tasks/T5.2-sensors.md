## Background

The controller has been reading the aircraft's exact state, which no real
aircraft can do. Real sensors report the truth plus a random wobble plus a slowly
drifting offset, and they report it only at their own update rate — a GPS at
5 Hz, a gyro at 200 Hz.

Three distinct effects, and they degrade a controller differently. **Noise**
mainly hurts derivative terms, which amplify it. **Bias** produces steady-state
error the integrator will chase. **Sample rate** adds delay, which eats phase
margin — and a controller with a 20 rad/s bandwidth reading a 5 Hz GPS is
operating on information that is already stale.

## What to implement

```python
class Sensor:
    """
        y = x_true + bias + noise
        bias_{k+1} = bias_k + w_k,   w_k ~ N(0, sigma_bias^2 * dt)

    Zero-order hold between samples: a sensor updating at 5 Hz returns the
    same value for 100 simulation steps at 500 Hz.
    """
    def __init__(self, rate_hz, sigma_noise, sigma_bias_walk,
                 rng: np.random.Generator, initial_bias=0.0): ...
    def measure(self, true_value: float, t: float) -> float: ...

class SensorSuite:
    """Gyro (3), accelerometer (3), GPS position (3), GPS velocity (3),
    pitot airspeed, barometric altitude, magnetometer heading."""
    def __init__(self, spec, rng: np.random.Generator): ...
    def measure(self, x_true: np.ndarray, xdot: np.ndarray,
                t: float) -> Measurements: ...
```

Starting values (MEMS-class, from the build guide):

| Sensor | Rate | Noise sigma | Bias walk |
|--------|------|-------------|-----------|
| Gyro | 200 Hz | 0.01 rad/s | 0.001 rad/s/√s |
| Accelerometer | 200 Hz | 0.05 m/s² | 0.005 m/s²/√s |
| GPS position | 5 Hz | 2.0 m | — |
| Pitot | 50 Hz | 0.5 m/s | 0.1 m/s |
| Barometer | 50 Hz | 0.5 m | 0.2 m |
| Magnetometer | 50 Hz | 2° | 1° |

**Every sensor takes an explicit `rng`.** No `np.random` calls anywhere. Phase 9
is worthless without this.

## Acceptance criteria

- [ ] Over 100,000 samples, measured noise sigma matches spec within 5%
- [ ] Bias performs a random walk: variance grows linearly with time
- [ ] **Zero-order hold verified.** A 5 Hz sensor returns identical values for
      100 consecutive 500 Hz steps, then changes
- [ ] **Reproducibility.** Two suites seeded identically produce identical
      sequences; differently seeded ones do not. Use `assert_array_equal`
- [ ] Sensors are independent — cross-correlation between channels is near zero
- [ ] An `ideal: true` config flag disables all noise and returns truth
- [ ] Sensors do not modify the true state

## Notes

Use `rng.spawn()` (NumPy ≥1.25) to give each sensor its own independent stream
from one parent seed. This means adding a sensor later does not change the noise
sequence of existing sensors, so Phase 9 results stay comparable across code
versions. It is a small thing that saves a full re-run.
