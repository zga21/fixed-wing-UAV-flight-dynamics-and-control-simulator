## Background

NDI's whole approach depends on its internal model being roughly right. So the
obvious question — and the one a reviewer will ask first — is: how wrong can the
model be before it stops helping?

This task answers it directly. Corrupt the controller's internal model by a known
amount, leave the true plant untouched, and measure performance as the error
grows. The PID does not use a model, so it should be flat; NDI should start
better and degrade. **Where those two curves cross** is the single most
informative number in Phase 6.

This is a controlled experiment, not a Monte Carlo. One parameter varies at a
time so the result is interpretable.

## What to implement

```python
def mismatch_sweep(parameter: str,
                   factors: np.ndarray,     # e.g. 0.5 to 1.5 in 21 steps
                   scenarios, seeds, cfg) -> pd.DataFrame:
    """
    For each factor:
      - build a ControlAffineModel with that parameter scaled (T6.1 perturb)
      - give it to NDI; leave the PLANT at nominal
      - run the standard scenarios with the standard seeds
      - also run the PID on identical cases as the flat reference

    One parameter at a time. Joint variation is Phase 9's job.
    """
```

Sweep at minimum: `C_m_alpha`, `C_m_delta_e`, `C_l_delta_a`, `I_yy`, and mass.
`C_m_delta_e` matters most — it appears directly in `g(x)`, so an error there
scales the inversion itself.

## Acceptance criteria

- [ ] At least five parameters swept over ±50% in at least 15 steps
- [ ] Each point averaged over ≥20 seeds, with error bars
- [ ] **Crossover identified and quoted** for each parameter: "NDI outperforms
      the tuned PID for `C_m_alpha` errors within ±X%"
- [ ] NDI at zero mismatch beats the PID — otherwise something is wrong in T6.2
- [ ] The PID curve is approximately flat, confirming it is model-independent
- [ ] Sign asymmetry noted: over-estimating a derivative usually hurts less than
      under-estimating it, because the inversion under-corrects rather than
      over-corrects. If your result shows the opposite, that is worth explaining
- [ ] `docs/mismatch_findings.md` states the crossover points in plain language

## Notes

These crossover values feed directly into Phase 9. If NDI degrades badly beyond
±20% error in `C_m_alpha`, then your Phase 9 uncertainty distribution for that
parameter — 15% standard deviation, so roughly ±30% at two sigma — will produce
NDI failures. That is not a problem with the experiment; it is the answer to RQ2,
and it makes the Monte Carlo result mean something specific.

Also: this sweep occasionally reveals that NDI is barely better than PID at zero
mismatch. If so, check that the inner loop is actually doing the inversion and
that the outer loops have not been re-tuned differently between the two.
