## Background

This is the payoff for all of Phases 1 and 2.

Every fixed-wing aircraft, from a paper glider to an airliner, has the same five
characteristic wobbles. A fast pitch bobble that settles in a couple of seconds
(short period). A slow, lazy exchange of height for speed that takes half a
minute per cycle (phugoid). A coupled yaw-roll waggle (dutch roll). A quick
settling of roll rate (roll subsidence). And a very slow spiral tendency that
may be gently divergent.

These are not something you design in. They **fall out** of correct equations.
So if your simulator produces all five, with frequencies in the ranges real
aircraft show, that is strong independent evidence that your entire physical
model is right. If a mode is missing or has a wildly wrong frequency, something
upstream is broken, and you have just found it before it cost you a month.

## What to implement

```python
@dataclass(frozen=True)
class Mode:
    name: str                    # 'short_period', 'phugoid', ...
    eigenvalue: complex
    omega_n: float               # |lambda|, rad/s
    zeta: float                  # -Re(lambda)/|lambda|
    period: float | None         # 2*pi/omega_d, None if real
    time_to_half: float          # or time to double if unstable
    is_stable: bool

def identify_modes(A_lon: np.ndarray, A_lat: np.ndarray) -> dict[str, Mode]:
    """
    Eigen-decompose and classify.

    Longitudinal: two complex pairs.
        - higher frequency  -> short period
        - lower frequency   -> phugoid
    Lateral: one complex pair + two real poles.
        - complex pair      -> dutch roll
        - fast real pole    -> roll subsidence
        - slow real pole    -> spiral

    Classification uses eigenvector participation where the frequency
    ordering is ambiguous, which happens at low airspeed.
    """

    """Returns a list of human-readable warnings for any mode outside the
    expected range. Empty list means everything is plausible."""
```

Expected ranges (from the build guide):

| Mode | omega_n | zeta |
|------|---------|------|
| Short period | 3–10 rad/s | 0.3–0.9 |
| Phugoid | 0.1–0.5 rad/s | 0.02–0.2 |
| Dutch roll | 1–5 rad/s | 0.05–0.4 |
| Roll subsidence | real, tau ≈ 0.05–0.5 s | — |
| Spiral | real, slow, may be unstable | — |

## Acceptance criteria

- [ ] All five modes identified at `V = 25` m/s
- [ ] Every mode falls inside the expected range, or the deviation is
      **explained in writing** in the test docstring
- [ ] Short period frequency increases with airspeed across the envelope
- [ ] Phugoid frequency approximately follows `omega_p ≈ g*sqrt(2)/V` — assert
      within 30%. This is a classic analytic approximation and matching it is a
      genuinely strong validation
- [ ] Roll subsidence time constant is roughly `-I_xx / (q_bar*S*b²*C_l_p/(2V))`
- [ ] Modes computed at 5 airspeeds; a root-locus-style plot saved to `docs/`
- [ ] `check_modes_plausible` returns an empty list

## Notes

If a mode is missing, the usual cause is that `reduce_to_euler_states` dropped
the wrong state or the decoupling in T3.2 mixed the subsystems.

If the phugoid comes out badly damped or unstable — that is normal. Real
phugoids are lightly damped, and a slightly unstable one is not a bug.

If the short period is at 40 rad/s or 0.4 rad/s, check `I_yy` and `C_m_alpha`.
That is almost always a config typo or a units error, which is exactly the class
of error this whole phase exists to catch.
