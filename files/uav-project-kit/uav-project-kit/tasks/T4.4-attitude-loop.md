## Background

The middle loop translates "bank 20 degrees" into "roll at this rate", and hands
that to the inner loop. It runs at 50 Hz — four times slower than the loop
beneath it.

That separation is not arbitrary. If two nested loops operate at similar speeds
they fight: the outer loop commands a correction, the inner loop has not finished
responding, so the outer loop commands more, and the result oscillates. Keeping
each outer loop 3–5x slower than the one inside it is what makes cascaded control
work at all.

def coordinated_turn_rate(phi: float, V: float) -> float:
    """
    Yaw rate for a coordinated (zero-sideslip) banked turn:

        r = g * tan(phi) * cos(theta) / V

    Without this the aircraft skids through every turn, sideslip builds, and
    the dutch roll mode is excited. Adding it is the difference between a turn
    that looks like an aircraft and one that looks like a simulation.

Rate limits on the commands matter: clamp `p_cmd` and `q_cmd` to physically
achievable values (say ±120 °/s) so the middle loop cannot ask for something the
inner loop can never deliver, which would wind up its integrator.

## Acceptance criteria

- [ ] 20° roll step: settles within 1.5 s, overshoot under 15%
- [ ] 10° pitch step: settles within 2 s, no steady-state error
- [ ] **Frequency separation verified.** Measured attitude-loop bandwidth is
      3–5x below the rate-loop bandwidth from T4.3. Assert this numerically
- [ ] **Coordinated turn.** A 30° banked turn holds `|beta| < 2°` throughout.
      Without `coordinated_turn_rate` this test should fail — verify it does,
      then re-enable
- [ ] Attitude commands beyond the envelope (e.g. 80° roll) are clamped to the
      envelope limit rather than passed through
- [ ] No integrator windup during a sustained 60 s turn

## Notes

The coordinated-turn test is a good one to save a plot from. Sideslip during a
turn is a subtle thing that a lot of simulator projects never notice is wrong,
and demonstrating that you handled it explicitly reads well.
