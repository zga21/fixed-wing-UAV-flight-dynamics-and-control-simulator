## Background

The atom of the campaign: one seed in, one row of results out. It must be
completely self-contained so that ten thousand copies can run in parallel across
processes with no shared state, and it must never raise — a crashed worker loses
the whole batch, whereas a recorded failure is data.

Everything random in the case derives from the single integer seed. That is what
makes any individual case reproducible later, which is essential for T9.5 when
you go and look at the worst failures.

## What to implement

```python
def run_case(seed: int, controller_name: str, scenario_name: str,
             spec: UncertaintySpec, cfg_path: str) -> dict:
    """
    One fully self-contained Monte Carlo case.

        rng = np.random.default_rng(seed)
        params  = sample_parameters(rng, spec)
        cfg     = apply_perturbations(load_aircraft(cfg_path), params)
        plant   = build_plant(cfg, rng.spawn(1)[0])
        ctrl    = build_controller(controller_name, tuned_gains)
        result  = run_scenario(scenario, ctrl, plant, cfg, rng=...)
        metrics = compute_metrics(result, scenario)

    Returns a FLAT dict, ready for a Parquet row:
        seed, controller, scenario, git_commit, config_hash,
        param_m, param_C_m_alpha, ...,          # every sampled parameter
        rmse_h, rmse_V, ..., success,           # every metric
        terminated_early, termination_reason,
        wall_time, guard_activations            # diagnostics from T6.2

    NEVER raises. Any exception is caught, recorded in `error`, and the case
    is marked failed. A worker that dies takes its whole batch with it.
    """
```

Record the sampled parameters in the row. Without them you cannot answer the most
interesting question the campaign can address: *which* parameter combinations
cause failure.

## Acceptance criteria

- [ ] Same seed, same output — every field, bit for bit
- [ ] Different seeds give different parameters
- [ ] Never raises: test with a deliberately broken controller, a diverging
      aircraft, and an invalid parameter set
- [ ] The returned dict is flat, JSON-serialisable, with a stable schema
- [ ] Wall time recorded per case
- [ ] Runs correctly inside a `multiprocessing.Pool` worker — test this
      explicitly, not just in-process
- [ ] Memory usage is bounded: do not retain full time histories except for
      cases explicitly flagged for export
- [ ] Guard activations from T6.2 recorded, so numerical failures can be
      distinguished from control failures in T9.5

## Notes

The stable schema matters more than it looks. If you add a metric halfway through
a campaign, older Parquet files will not concatenate with newer ones. Version the
schema, and write the version into every row.
