## Background

The objective function is where you write down, as a single number, what "good
flying" means. The optimiser will pursue it literally and without judgement, so
whatever you forget to penalise, it will exploit.

Leave out control rate and it will find gains that chatter the servos to
destruction. Leave out saturation and it will command far more than the actuators
can deliver. This is the task where being careful pays for itself.

Two technical points matter more than the weights. **Normalisation:** tracking
error is in metres-squared-seconds and control effort is in radians-squared-
seconds, so without normalising, the weights are meaningless and one term will
silently dominate. **Failure handling:** a diverged run must return a large
finite number, not NaN, or the optimiser cannot rank it.

## What to implement

```python
FAILURE_COST = 1e6

def evaluate_gains(k: np.ndarray,
                   controller_factory: Callable[[np.ndarray], Controller],
                   scenarios: list[Scenario],
                   cfg, weights: ObjectiveWeights,
                   n_workers: int = 1) -> float:
    """
    J = mean over scenarios of:
        w1*E_track~ + w2*E_rate~ + w3*U_ctrl~ + w4*P_sat + w5*P_viol

    Tilde denotes normalisation by the BASELINE's value for that term
    (docs/baseline_record.json), so J = 1.0 means 'as good as the untuned
    baseline'. This makes the weights dimensionless and interpretable, and it
    makes J directly comparable between the two controllers.

    Returns FAILURE_COST (finite, not NaN) if a scenario diverges, hits NaN,
    or leaves the envelope. The optimiser must be able to order failures.

    MUST be deterministic: same k, same scenarios -> same J, bit for bit.
    """

@dataclass(frozen=True)
class ObjectiveWeights:
    w_track: float = 1.0
    w_rate: float = 0.1
    w_ctrl: float = 0.05
    w_sat: float = 2.0
    w_viol: float = 10.0
    regularisation: float = 0.0    # lambda * ||k||^2, if overfitting appears
```

The terms, from the build guide:

```
E_track = integral ||r(t) - y(t)||^2 dt
E_rate  = integral ||delta_dot(t)||^2 dt
U_ctrl  = integral delta^T R delta dt
P_sat   = fraction of time any surface is saturated
P_viol  = sum over constraints of max(0, (c - c_max)/c_max)^2
```

## Acceptance criteria

- [ ] **Deterministic.** Called twice with identical arguments, returns a
      bit-identical float. Test with `==`, not `approx`
- [ ] Baseline gains from `docs/baseline_record.json` give `J ≈ 1.0`
- [ ] Deliberately bad gains give `J > 1.0`
- [ ] A diverging gain set returns exactly `FAILURE_COST`, never NaN or inf
- [ ] Each term is individually testable and reported alongside `J` — you will
      need the breakdown to diagnose what the optimiser is actually chasing
- [ ] Parallel evaluation gives bit-identical results to serial
- [ ] Evaluation time measured and recorded; the budget in T7.3 depends on it
- [ ] Weights live in a committed YAML, not hard-coded

## Notes

Before running the optimiser, sanity-check the objective by hand: perturb one
gain in each direction and confirm `J` moves the way you expect. An objective
with a sign error will happily converge to the worst controller it can find, and
that is a genuinely confusing afternoon.

Log the term breakdown for the best individual at every generation. When the
optimiser does something surprising, the breakdown tells you which term it found
a way to game.
